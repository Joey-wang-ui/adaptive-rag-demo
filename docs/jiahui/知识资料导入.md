# 嘉惠文本知识资料导入

产品结构化CSV之外，业务说明、供应商资料、PDF逐页文本采用显式知识清单。它们存放于 `data/jiahui/knowledge/`，不会读取原电商 `knowledge/`。未登记在独立清单中的文件不会进入知识问答。原文只作为证据，文档中的指令不授权执行任何操作。

## 单份资料

在仓库根目录，用当前虚拟环境执行：

```bash
.venv/bin/python -m app.jiahui.import_knowledge --source "业务说明.md" --id "业务说明-第二章" --version "2026-04待确认" --location "第2章" --status reference --scope knowledge --data-dir data/jiahui
```

Windows 将 `.venv/bin/python` 替换成 `.venv\Scripts\python.exe`。支持 UTF-8 `.md` 或 `.txt`，不直接解析PDF、Word或Excel。原件应另行留存在 `data/jiahui/sources/`。

- `--id`：稳定文档/章节ID，不因版本变化修改。分页PDF每页使用独立ID。
- `--version`：来源版本标签；不清楚时明确写“版本待确认”，不能从文件创建时间推断。
- `--location`：必须给页码或章节。PDF需要与原页序对应，不能只写“附件”。
- `--source-file`：可选，原文件相对名称，例如 `杭州嘉惠目录表2026年4月修改(2)(1).pdf`；缺省为文本文件名。
- `--title`：可选，便于引用显示的资料标题。
- `--scope`：单个访问范围，默认 `knowledge`，也可用 `procurement` 等与账号scope一致的范围。
- `--effective-date`：可选，仅明确提供的 `YYYY-MM-DD`；未来生效资料在生效前不进入问答。
- `--status`：默认 `draft`；`reference` 表示只作参考、尚未确认现行，不得作为现行制度；`current` 表示业务已确认当前适用；`historical` 仅留档，不进入问答。

只有获授权范围内的 `current`、`reference` 文本进入检索。资料的状态、版本和位置进入来源引用。正式业务政策必须经业务核对后设置 current；不能把电商演示政策、目录文件名或供应商描述自动当作嘉惠制度。

新版本继续使用同一ID，修改 `--version`。导入新的 current/reference 版本时，原ID的旧 current/reference 版本会设为 historical。导入 draft 不替换现行版本。未来版本应先以 draft 准备，到明确生效时再切换。清单写入前自动备份，原文以内容摘要命名且不覆盖旧原文；恢复旧清单时，其引用的旧原文仍保留。同一输入重复导入为无变化操作。更新不会隐式删除未出现在本次操作中的其他资料。

## 用户提供的22页目录：按页作为未确认现行的参考资料

资料准备目录已经保留原PDF和逐页文本：

`data/jiahui/sources/catalog-2026-04/page-01.txt` 至 `page-22.txt`。

原件共22页，产品正文为第4—22页。第1页封面、第2—3页目录无需作为产品问答依据。下列命令只将正文登记为 reference，保留PDF原文件名和每页位置；它不会创建经过核对的商品SKU，也不表示保质期、现行价格、库存、订单、食品功效或替代适用性已经确认。

Linux/macOS，仓库根目录：

```bash
(
set -e
for page in $(seq 4 22); do
  page_file=$(printf 'data/jiahui/sources/catalog-2026-04/page-%02d.txt' "$page")
  .venv/bin/python -m app.jiahui.import_knowledge \
    --source "$page_file" \
    --id "jiahui-catalog-202604-page-$page" \
    --version "2026年4月目录-现行状态待确认" \
    --location "PDF第${page}页" \
    --source-file "杭州嘉惠目录表2026年4月修改(2)(1).pdf" \
    --title "嘉惠目录 第${page}页" \
    --status reference --scope knowledge --data-dir data/jiahui
done
)
```

Windows PowerShell，仓库根目录：

```powershell
foreach ($pageNumber in 4..22) {
  $sourcePage = 'data/jiahui/sources/catalog-2026-04/page-{0:D2}.txt' -f $pageNumber
  .venv\Scripts\python.exe -m app.jiahui.import_knowledge --source $sourcePage --id "jiahui-catalog-202604-page-$pageNumber" --version "2026年4月目录-现行状态待确认" --location "PDF第${pageNumber}页" --source-file "杭州嘉惠目录表2026年4月修改(2)(1).pdf" --title "嘉惠目录 第${pageNumber}页" --status reference --scope knowledge --data-dir data/jiahui
  if ($LASTEXITCODE -ne 0) { throw '资料导入失败，请检查上方错误；不要继续后续页面。' }
}
```

服务端每次查询重新读取独立清单和产品文件；已运行的服务无需修改电商索引。导入前仍建议备份整个 `data/jiahui`。清单备份位于 `data/jiahui/knowledge/backups/`；原文位于 `data/jiahui/knowledge/documents/`。异常中断遗留 `.knowledge-import.lock` 时，先确认导入进程已退出，再手动移除锁；不能自动抢占另一个导入。

## 目录核对注意

这份PDF存在真实编号冲突：例如1564、1672、1702、1703分别指向不同商品。单页原文引用不代表所有表格行已准确结构化。某些储温字段与名称中的温度冲突，一行可能包含多个包装规格，部分规格缺单位。遇到同名多规格、编号多义或冲突时应先明确产品/规格/来源，不凭相邻表格推断。制作结构化产品目录时请使用本目录 `产品目录模板.csv` 并逐条核对。文件提及的“冻转鲜”附页并未包含在这22页中。

## 产品来源与权限一致性

产品目录原文必须使用与产品记录一致的权限标签（公共产品目录为 products），不能借用宽泛的 knowledge 权限绕开产品范围。含不同保密级别的文档应拆成按权限独立的章节，或将整份文档设为最严格范围；同一资料的CSV和原文应同步调整访问范围。正式导入后每次请求重新过滤权限和版本，不共享跨权限检索/答案缓存。
