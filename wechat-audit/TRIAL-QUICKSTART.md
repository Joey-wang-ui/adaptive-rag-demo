# 嘉惠审核工作台 · Windows 试用版 0.5

这是独立审核工作台与微信只读试验版，不是已验收的无人值守微信机器人。

## 下载后怎样打开

1. 完整解压 `JiahuiAuditTrial-Windows.zip`，不要在压缩包里直接运行。
2. 双击 `JiahuiAuditTrial.exe`。旁边的 `_internal` 文件夹必须保留；无需另装 Python、Node 或 Ollama。
3. 第一次先点“载入演示材料”，熟悉操作。打开软件不连接微信，不调用模型，不发送消息。

目前为未签名试用软件。Windows 提示来源未知时，请核对下载来源与发布页 SHA-256；是否允许运行由你的电脑管理策略决定。

## A：不联网先测数量审核

1. 打开“确认订单”，点击“载入演示材料”。示例：演示烘焙店、DEMO001、蛋液 10kg、10 箱、85 元/箱、850 元。
2. 检查字段，点击“保存为已确认订单”。
3. 切到“出库单审核”，选择 DEMO001，点击“核对字段后开始审核”，应显示“已识别字段无差异”。
4. 双击出库单商品行，把数量改为 9，保存后重新审核，应提示数量不同和行金额问题。

手工录入也可完全离线使用。已确认订单不可覆盖；有修改时请用新版本订单号，以免旧材料悄悄套用新订单。

## B：接 DeepSeek，审核真实照片

1. 点击“模型设置”，填写自己的 DeepSeek API Key。
   - Base URL：`https://api.deepseek.com`
   - 模型：`deepseek-chat`
2. 在“确认订单”选择最终确认订单照片，识别后逐项核对客户、订单号、商品、规格、数量、单位、成交单价和金额，再点击保存。
3. 在“出库单审核”选择对应的已确认订单，选择发货单/出库单照片。
4. 核对识别结果，缺失字段需人工补齐，不会猜订单号或默认单位。点击开始审核，查看结果；历史结果自动保存在本机。

Key 仅在本次软件进程中使用，不写文件。关闭软件后需重新填写。照片在本机 OCR，识别出的文字发送至你选择的模型服务；使用 DeepSeek 按其规则计费。最终数量、单价和金额对比由 Python Decimal 规则完成，模型不决定是否批准发货。也支持其他 OpenAI 兼容 Chat Completions 服务，切换地址后须重新填写对应 Key。

审核提示“无差异”也不等于批准发货；仍须人工核对原图和实物。

## C：微信只读试验

1. 只在授权测试账号/群上试，不连接真实客户业务。
2. 电脑登录微信，并手动把名称唯一的测试群打开成独立聊天窗口。
3. 切到“微信只读试验”，填写完整群名。
4. 点击“准备并校验诊断组件”。此按钮从用户指定 GitHub 仓库下载固定提交源码，校验 SHA-256，在本机隔离副本中禁用删除微信更新文件的函数；没有把第三方源码预装进此下载包。
5. 点击“启动 120 秒只读诊断”，由群里另一个成员发送编号消息。
6. 你可在 VS Code 输入、手动最小化窗口做对照。结束后查看窗口输出；“打开本地数据目录”可找到诊断数据库和日志。“停止本次诊断”只终止本软件启动的诊断进程，不关闭微信。

上游仅声明支持微信 4.0.5，未保证兼容你的版本；最小化后可能接收失败。当前只记录显示名、UI runtime ID、本地接收时间、消息类型/文本，以及前台窗口/剪贴板序号采样；**不下载微信原图、不自动关联订单、不调用审核、不回复群消息**。真实 @ 身份和跨重启消息完整性仍未验收。第三方项目许可证尚待维护者明确，正式商业使用或分发前需确认授权；不要因为支持旧版而直接降级日常微信。

## 数据在哪

点击“打开本地数据目录”，目录为 `%LOCALAPPDATA%\JiahuiAuditTrial`：

- `jiahui.sqlite3`：确认订单及审核结果。
- `wxauto4-trial.sqlite3`：只读试验观测。
- `wxauto4-probe.log`：诊断输出。
- `wxauto4-reviewed`：按需准备的固定版本 SDK 隔离副本。

本软件不包含用户认证或多岗位审批，只限本机可信操作者试用；不修改库存，也不自动批准发货。不要把数据目录、API Key 或真实客户单据发到公开仓库。
