# 指定微信群审单：Windows 试运行配置

**v0.3 推荐简化模式：直接发订单文字、单据图片或图文混合（合计1～4份），再 `@审单bot 审核`。不需要标签或编号，只有出货单也能自查。也可同一条消息首行 @审核、下面粘贴正文。软件内修改审核要求、其他 LLM 接口配置见 [DESKTOP.md](DESKTOP.md)。以下标签流程作为旧版兼容方式保留，不是简化模式的要求。**

此适配器复用 wechatbot-new 使用的 `wechatauto-replica==1.2.8.1` 收发底层，接本仓库现有的 OCR、DeepSeek 字段提取和 Decimal 核对。**不需要安装 wechatbot-new 完整聊天程序、小漓、OpenClaw、Node 或 Ollama**。这是一份新增实验适配器，不是上游已验证的完整审单产品。

已在 Linux 测试群范围、触发、材料关联、金额核对；**尚未在你的 Windows 微信 4.2.0.6 实测读取、原图及发送**。上游实测版本主要为 4.1.15。检测失败时停止，不宣称连接成功。

## 首次配置

1. 退出小漓和其他自动回复程序。电脑版微信只登录一个测试账号，加入一个名称唯一的测试群，打开该群并让其他成员发一条新消息。程序不以管理员身份运行。
2. 双击根目录 `setup-group-audit.cmd`。需要 Python 3.12（`py -3.12`），首次安装独立 Python 环境与 OCR/群读取依赖。填写**唯一群名**和**机器人在这个群的昵称**。
3. 检查屏幕显示的账号、群名与群 ID。这个步骤仅验证文字读取，**不发消息、不调用 API**。若识别不正确，关闭窗口，修改或删除 `wechat-audit/data/group-audit/config.json` 后重做。
4. 确认身份正确后双击 `start-group-audit.cmd`，首次隐藏输入 DeepSeek Key。仅保存到本机 `wechat-audit/data/group-audit/api-key.txt`；后续启动复用。也支持 `DEEPSEEK_API_KEY` 环境变量。不要分享整个 data 文件夹。
5. 启动窗口保持打开。此时仅对**启动之后**指定群的明确 `@昵称 审核 编号` 自动回群；Ctrl+C 停止。不自动补发离线期间的审核，也不自动重试可能已经发送的回复。

## 群内用法

每张图片前必须先发一条标签，**由同一个群成员在120秒内紧接着发图**：

```text
订单 A001
（下一条发送客户最终确认的完整订单图片）
出货单 A001
（下一条发送本次完整出货单图片）
@审单bot 审核 A001
```

最后一句用微信的真正 @ 选择机器人账号，昵称换成设置值。图片标签不需要 @，不会自动回复，也不调用模型；只有审核指令才提取字段并核对。别人插话不占用你的图片标签；**自己插入其他消息会取消自己的待接收图片状态**。重发标签立即撤销该角色旧材料，防止旧单被当新单审核。每单据限一张完整原图、30行商品；多页先整理为独立单据。建议编号包含日期，不复用旧订单号。

图片原图可能尚未存到电脑上：如果报告“未取得原图”，在电脑版微信打开两张图并点查看原图，再重新 @审核。适配器不自动点击下载，不把缩略图当原图。底层图片解密仍可能不兼容当前版本；失败不能靠提示词修复。

也支持纯文字测试：一条消息包含标签、换行及完整正文，例如：

```text
订单 A001
客户：测试店；关联订单号：A001；蛋液，规格10kg，数量2箱，单价50元/箱，金额100元；合计100元。
```

出货单同样格式，最后 @审核。仅标签不带正文时下一条必须是图片。OCR 在本机运行，识别的单据文字发送到 DeepSeek **文字 API `deepseek-chat`**，无需视觉模型，API 仍按实际用量收费。识别结构化字段可缓存，重新 @但材料未改时不重复模型调用；材料超过24小时要求重发。

## 固定行为

- 单个群绑定真实 `@chatroom` ID，拒绝同名歧义；忽略私聊、其他群、自身消息、发送者身份不明的消息。
- 不是聊天机器人：不闲聊、不读朋友圈、不发提醒、不自动更新、不转发其他人的聊天。模型输出不作为微信命令执行。
- 每个群成员都能提交材料和请求审核，没有销售/负责人岗位权限区分。群成员发给本机器人的文字形式 @ 是匹配依据，不声称验证了官方服务端 mention 元数据。
- 结果自动回指定群；无差异也不代表批准发货。没有库存扣减、财务过账或群内“确认放行”命令。
- 实际装货、最新成交价和订单最终版本由人确认；两份单据同错、模糊扫描和 OCR 表格错行不能靠金额核算自动识别。

## 本地文件

`wechat-audit/data/group-audit/config.json` 示例（第一次检测自动生成真实绑定，不要抄示例账号）：

```json
{
  "group_name": "嘉惠审单测试群",
  "bot_nickname": "审单bot",
  "binding": {"account": "由检测填写", "group": "由检测填写@chatroom"}
}
```

data 内含 Key、单据、字段和去重记录，全部 Git 忽略。底层第三方库还会在用户目录保存解密密钥/本地数据缓存，具体见其说明。它会读取微信本地数据库与进程内存，发送使用界面自动化，**不是腾讯官方群机器人接口**。应遵守微信规则与公司数据要求；试用先用无客户信息的测试单。

源码与 Apache-2.0 许可证：[wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica)。本包没有复制 wx4py 或 wechatbot-new 的代码；仅使用相同的底层依赖。
