# 微信 4.2.0.6：先做实机只读检查

当前已交付的官方微信机器人只支持私聊。用户希望读取现有普通微信群；公开候选库的说明未确认兼容 **4.2.0.6**，因此本目录新增的是**Windows 实机检查器和实验性的可见群文字观察器**，不是已验证可用于公司的群审单接入。

## 操作

1. 完整解压新版 ZIP，双击根目录 `check-wechat-groups.cmd`。
2. 首次安装独立的小型 UI Automation 环境；此检查不需要 DeepSeek Key、OpenClaw 或 OCR 依赖。
3. 输入一个你有权限读取的**测试群的完整名称**。
4. 在 8 秒倒计时内切到电脑版微信，手动打开该测试群，保持窗口展开、消息在底部。
5. 查看终端结果。能同时验证群标题和消息列表时，程序显示本机样本并观察新界面记录。可用手机手动发一条测试文字，检查终端是否出现它。Ctrl+C 停止。

只观察手动打开的这个群，不会搜索所有聊天、切换群、点击图片或自动发消息。切到其他聊天后会暂停；当前是 UI 检测，不能承诺获取后台所有群、完整历史、锁屏期间内容或每一条消息。

测试群请使用唯一、可区分的名称；群名不是稳定的微信会话 ID，这个检测器不作为生产环境的身份或权限边界。

## 检查结果

诊断文件：`logs/wechat-group-compat.json`。

报告保存程序版本、控件类型、类名、层级、坐标和名称长度。群名用摘要代替，聊天原文不写入报告，也不发送到任何 API。可以将这个脱敏文件提供给开发者继续适配。聊天样本只在自己的终端显示，分享终端截图前自行检查其中是否有业务内容。

若提示无法找到群标题或消息列表，**不能认定 4.2.0.6 兼容**，需要根据本机控件结构继续适配。检测器不会要求降级微信、输入账号密码、注入微信进程或读取微信数据库。

即使终端能显示群文字，也只证明了当前可见界面的文字通路；**图片占位提示不等于拿到单据原图**。本版没有实现图片原文件获取，也没有连接群审单。必须分别验证原图获取、订单关联与最终确认规则，才能接后续自动审单。

原理是 Windows UI Automation。它是非官方微信自动化接入，不是微信提供的群消息 API；兼容性、客户端更新和账号规则需要在实际使用中评估。本轮仅使用测试群进行只读验证。

依赖：[uiautomation](https://github.com/yinkaisheng/Python-UIAutomation-for-Windows)（Apache-2.0）、comtypes。没有采用仅标注较老微信版本或商业授权情况不清晰的微信自动化封装库。
