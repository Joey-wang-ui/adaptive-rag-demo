# 微信私聊发货前审单助手（试运行）

面向嘉惠的小范围试用：把**客户最终确认订单**与**出货单**分别发给微信助手，识别字段、核对差异，记录操作者的人工确认。现有 RAG 网页继续使用 `start-api.cmd`；本模式使用独立的环境和数据目录。

**需要自动读取现有普通微信群：** 先运行根目录 `check-wechat-groups.cmd`，在自己的 Windows 微信 4.2.0.6 上验证界面可读性。它是独立的只读检测器，不调用 API，尚未实现单据原图获取或群自动审单。详见 [群聊实机兼容性检查](GROUPS.md)。

群审单目标采用 `@审单助手 审核 订单号` 才触发。检测器已加入可见 @ 文本门控，普通聊天不输出、不调用模型；实际微信 @ 元数据和原图仍需实机验证。

## Windows 启动

1. 完整解压项目到较短的目录，例如 `%USERPROFILE%\jiahui-bot`，不要在 ZIP 内直接运行。
2. 双击根目录 **`start-wechat-audit.cmd`**。需要已安装的 Python 3.12 和 Node 24.22.1+（24.x）或 26.12.1+。
3. 首次运行自动安装依赖。图片用小型 OCR 模型识别，不下载 Ollama 或本地语言模型。OpenClaw、OCR 及依赖会占用磁盘，首次安装需要联网。
4. 程序优先复用环境变量、`wechat-audit/data/.env` 或项目根目录 `.env` 中的 `DEEPSEEK_API_KEY`。没有时会隐藏输入并仅保存到本机 `wechat-audit/data/.env`，后续启动复用。
5. OCR 加载、真实 API JSON 生成和插件注册检查通过后，使用手机微信扫描**官方插件生成的二维码**并确认授权。扫码、验证码和密钥都不需要发给开发者。
6. 启动窗口保持打开，在新出现的微信机器人私聊中发送 **`帮助`**。收到回复才算微信消息链路在这台电脑上实际跑通。

电脑关机、断网或关闭启动窗口后机器人停止。重新双击启动文件即可复用依赖、密钥和微信登录；登录过期时需重新扫码。当前不是云端全天候服务。

## 第一笔测试订单

先用虚构数据，按顺序在同一微信私聊发送：

```text
新建 TEST001
```

```text
订单
```

然后发送**一张完整的客户最终确认订单图片**。

```text
出货单
```

然后发送**一张完整的出货单图片**。收齐后会自动回复识别明细和差异。也支持用完整文字代替图片：

```text
订单 客户：测试烘焙店；商品：巴氏蛋液，规格10kg，数量10箱，成交单价85元/箱，小计850元；合计850元。
```

```text
出货单 客户：测试烘焙店；商品：巴氏蛋液，规格10kg，数量12箱，单价88元/箱，小计1056元；合计1056元。
```

预期返回数量和单价差异，而不是“已批准发货”。这两段是测试文本，不是公司的真实价格或交易。

其他命令：

| 命令 | 用途 |
| --- | --- |
| `帮助` | 显示步骤 |
| `新建 A001` | 新建或打开当前微信操作者自己的订单 |
| `订单` / `出货单` | 指定下一份材料；同时使旧报告和旧确认失效 |
| `查看订单` / `查看出货单` | 查看已提取字段 |
| `审核` | 对当前版本重新核对 |
| `确认 A001 v2` | 对指定、已核对且无差异的版本记录人工确认 |

发新图前先发 `订单` 或 `出货单`。不要混发多个订单。第一版每份材料一张完整图片，每单最多 30 行，单图不超过 12 MiB / 3200 万像素；多页材料先拆单，不自动拼接。PDF、Excel、语音、视频不作为审单输入。

## 核对边界

- 名称、规格、编码、数量、数量单位、成交单价、计价单位、行金额和合计。
- 金额由十进制程序计算，按分四舍五入；一分钱差异也会报告。
- 不把箱、件、袋、公斤自动换算；单价按箱还是按公斤不明时须补充确认。
- 使用这笔订单提供的成交价，不从网上猜价，不把新价格表套回旧订单。
- 识别模糊、缺字段、重复行、折扣、运费、税费或分批发货的歧义进入人工核对。
- 不会凭聊天指令忽略差异、自动生成放行结果。更换材料后旧确认作废。
- AI 结果仍需对照原图；实物是否装对由备货/审核人员检查。

**本版是单操作者的审单辅助原型，人工确认记录来自当前微信操作者，尚未实现销售与审批负责人分岗、跨员工共享订单或 ERP 库存联动。** 不把它直接当作已经上线的公司审批制度。先用历史单据测识别、漏报和误报，再确定正式岗位权限。

## 微信能力与账号授权

传输使用腾讯发布的 `@tencent-weixin/openclaw-weixin@2.4.10`，固定 OpenClaw `2026.10.8`。官方插件当前只支持私聊，不能加入现有普通客户微信群自动读群。

机器人是否能绑定、是否需要额外验证，以你手机的官方登录结果为准。程序不会模拟微信客户端、读取个人号全部聊天或绕过平台权限。

若微信提示配对码，先在启动窗口按 Ctrl+C 停止，然后在项目根目录 CMD 执行：

```cmd
py -3.12 wechat-audit\bootstrap.py --pair
py -3.12 wechat-audit\bootstrap.py --pair 你手机显示的配对码
```

核对请求人后再执行第二条。完成后重新双击启动文件。需要重新扫码时：

```cmd
py -3.12 wechat-audit\bootstrap.py --login
```

每个授权私聊的数据独立存放。第一版不自动共享其他员工的单据。

## 数据和运行方式

```text
微信私聊 → 腾讯官方插件收图/解密 → 本机 OCR
       → DeepSeek 提取结构化字段 → 本机十进制核对
       → 微信返回疑点 → 操作者明确确认指定版本
```

图片在本机 OCR；提取出的单据文字发往配置的 DeepSeek API，因此会产生 API 用量。原图由官方插件在本机管理，业务字段、证据片段和确认事件保存在 `wechat-audit/data/audit.sqlite3`。这些目录及密钥被 Git 忽略，不打进下载包。

OpenClaw 使用本项目独立的配置目录、只监听本机的端口；通用 Agent 工具全部禁用。审单插件拦截本通道消息，故障时返回未完成，不转给另一个 Agent 猜答。无需公网 IP 或把电脑端口映射到互联网。

本地日志：`logs/wechat-plugin-check.log`、`logs/wechat-audit.log`。不要公开上传整个 `wechat-audit/data`，其中包含本机凭据和业务记录。

## 开发验证

```bash
python -m pytest wechat-audit/tests -q
node wechat-audit/tests/plugin.test.mjs
```

测试覆盖差异核对、Decimal 金额、计价单位、缺失和模糊字段、版本失效、重复消息、用户隔离、确认限制、附件路径和本机接口鉴权。开发时另做真实 OCR 图片和真实固定版本 OpenClaw 插件加载检查。没有用户微信扫码和 API 凭据，开发环境的测试不能证明用户账号已连接。

框架和传输来源：[OpenClaw](https://github.com/openclaw/openclaw)、[腾讯微信渠道插件](https://github.com/Tencent/openclaw-weixin)。审单流程、规则、启动器和本机服务在本项目中实现；不修改腾讯插件源码。
