# 嘉惠微信群审单助手 · 桌面版

## 已安装 Python 的启动方式

完整解压仓库 ZIP，双击根目录 **open-group-audit.cmd**。使用电脑已有的 Python 3.12 / Tkinter；首次检测自动安装依赖。在窗口里操作，不用输入终端命令。所有配置沿用 `wechat-audit/data/group-audit`。

## Windows 软件包

仓库 Actions → **Build Windows group audit desktop** → 成功的运行 → 下载 **JiahuiGroupAudit-Windows**。

完整解压后双击 **JiahuiGroupAudit.exe**。保留旁边的 `_internal` 文件夹，不能只复制 exe。打包成功并通过内置 OCR/依赖检查后才上传软件包；这不代表微信收发通过测试。软件包不需要另装 Python/Node/Ollama，首次仍需 DeepSeek Key 和电脑微信。

这是未签名的试运行应用。源码、依赖和 Windows 构建过程都在此仓库。

## 使用

1. 退出其他微信机器人，在电脑微信登录一个测试账号，打开名称唯一的测试群。
2. 填群名、机器人在群里的昵称、模型 API Key（默认 DeepSeek）。Key 遮挡显示；“记住 API Key”可选，仅保存到本机，不上传到仓库。
3. 点击 **检测连接**。此步骤只检测账号和群文字读取，不发消息、不调用模型。
4. 检查窗口显示的账号和群，正确后点击 **启动审单**。只有显示“运行中”后才开始监听。
5. 任务运行时可随时按 **Esc 全局急停**：即使微信在前台、本软件已最小化也有效。也可点击 **停止**。急停会终止本软件启动的 worker 及其子进程，中断其微信、鼠标键盘自动操作；主窗口和微信保持打开，不结束其他程序。正在发送或已经发出的消息无法撤回。
6. 停止后不会自动恢复，必须手动点击 **启动审单**。Esc 只在检测 / 审单任务期间注册，任务完全停止后释放。若快捷键被其他程序占用、无法注册或进程隔离失败，会明确报错并阻止启动自动操作。
7. 关闭主窗口也会清理本软件自己的任务，不最小化到托盘继续运行。

v0.4 群内图文用法：

```text
（发送订单文字、单据图片，或两种材料混发；合计最多4份）
@审单bot 审核
```

不要求标签或编号，支持“帮我审核一下”“帮我看下这张单”等简单指令。默认取本人最近10分钟最新一批材料，连续材料间隔不超过2分钟。已审核后新发的材料会开新一批，避免混入旧单。请求者没发材料时，仅在近期恰好一位成员有尚未审核的材料时使用其材料；多人有未审核材料时请提交者本人 @，不猜审核对象。一次最多4份，文字和图片一起计数。建议同一个人提交本次图文材料。普通消息不回复。

## 一个微信号自己测试

默认忽略当前登录账号自己发送的消息。需要自测时，先停止审单，勾选主界面的 **允许自己触发测试**，再启动。只在指定群生效，不支持文件传输助手或给自己私聊。启动前的消息不补读。

在指定群里，用电脑或手机上的同一账号发订单文字或图片，再**手动输入** `@审单bot 审核`（昵称替换成软件填写的群昵称，后面留一个空格）。微信通常不能在成员选择中 @自己，本软件测试模式识别这段手动输入的文字。也可发一条 `@审单bot 审核`，换行后粘贴完整订单正文。

自动回复带有 `【嘉惠审单助手回复】` 标记，程序不把这些回复再当材料或指令。自测结束后停止软件、取消勾选再启动，恢复忽略自己消息的正常模式；勾选状态会保存在本机。

## 已处理材料不重复审核

同一批材料完成识别并生成审核结果后，之后仅重复 @审核将静默跳过：不再识别、不调用模型、不重复回群，也不会换去审核别人的材料。即使发现问题，也算本批已审核；修正后请重新发送本次完整材料，再 @审核。新发送材料表示新一轮提交，软件不承诺识别不同照片是否属于同一张业务订单。若审核结果回群失败，请重新提交材料，不自动补发。

未取得原图或模型提取失败的批次不记为已完成，可以解决问题后重新 @审核；同批已识别的部分使用缓存，不重复调用模型。启动时只监听之后的新消息；自动批次在重启后清空，不补读旧单。旧版带编号流程也跳过同一版本材料已完成的审核，并保留该记录到本机数据库。

普通订单文字中有数量、价格、金额等订单信息时，会先在本机暂存为候选，不立即调用模型。例如单独发“王记店订货：蛋液2箱，每箱50元，金额100元，合计100元”，再 @审核。一般闲聊不进入审单候选。文字不完整、被当普通聊天跳过或担心选错时，直接在同一条消息里指定正文：

```text
@审单bot 审核
王记店订货：蛋液2箱，每箱50元，金额100元，合计100元。
```

也可把 @审核放在完整正文的最后一行。每份文字上限20000字、30行商品；暂不自动合并多条零散文字为一张订单。微信合并转发的聊天记录、语音、PDF/Excel不等于普通文字，本版仍未接入。单独文字不需要获取图片原图或执行 OCR。

只有出货单也能检查行金额、合计、缺项，不能验证实际成交价或错发漏发。只有两张图明确识别为订单/出货单、客户一致、关联订单号明确一致时才自动比对；否则分别自查。类型不明的图片也会尝试单据自查，不猜类型。每张最多30行，多张跨页图片不自动拼接或合并总计。启动前的图片不补读，重启后请重新发图。旧版标签流程保留兼容。

识别后的结果自动回指定群。若原图获取失败，先在电脑微信打开图片、查看原图，再重新 @审核。

## 在软件里改审核要求、接其他 LLM

先停止审单，点击 **模型与审核设置**：

- **Base URL**：默认 `https://api.deepseek.com`。可填写其他平台的 `https://平台地址/v1` 或完整 `/chat/completions` 地址。仅支持 OpenAI 兼容的 Chat Completions，模型须支持文字及 JSON 对象输出；不是所有平台的原生协议都能直连。本机可用 HTTP，公网须用 HTTPS。
- **模型名**：按平台填写，不自动猜可用型号。切换接口地址后会清除旧 Key，请回主界面填写新平台的 Key，避免将旧密钥发到新平台。
- **审核要求**：可勾选客户名称/规格缺失是否提醒，填写商品简称、包装写法和关注点等补充要求。默认不要求固定单据模板。金额核算、单位不清提示和不自动批准发货始终保留，不能靠提示词关闭。

保存后重新启动生效。图片在本机 OCR，提取出的文字和补充要求发送给所选模型；不需要视觉模型。费用、限流与 JSON 模式支持以平台为准。此更新不会替你创建账号或申请免费额度。

详细规则见仓库 `wechat-audit/GROUP-AUDIT.md`。Key/单据/日志均在本机；打包版目录为 `%LOCALAPPDATA%\JiahuiGroupAudit`，窗口提供“打开数据目录”。不要把这个目录发给别人。关闭“记住 Key”并点击检测/启动会删除软件保存的 Key 文件；当前进程仍可使用界面里输入的 Key。

桌面界面只是操作入口；微信 4.2.0.6 的读取、原图、自动回群仍需在你的电脑验证。底层使用非官方界面自动化与本地数据库/进程内存读取；软件不会自动批准发货或修改库存账目。先用没有客户信息的测试单据。
